# Development setup

Everything you need to build, run, and test Ashfall locally. If you just want the
30-second version, it's in the [README](../README.md#run-it); this page is the
one to reach for when something doesn't work.

New contributor? Pair this with [`CONTRIBUTING.md`](../CONTRIBUTING.md) (workflow
and standards) and the [codebase tour](codebase-tour.md) (where things live).

## What you need

| Tool | Version | Needed for |
|---|---|---|
| **.NET SDK** | **10.x** | everything — it also builds the net8.0 libraries |
| **Godot** | **4.3+**, the **.NET / Mono** build | running/editing the client |
| **Docker** | any recent | Postgres for the gateway + persistence |
| **Python 3** | 3.8+ | regenerating placeholder art (optional) |

Notes:

- Installing the **.NET 10 SDK is enough** to build and test the server, gateway
  and `sim-core`. You only need the **.NET 8 runtime** separately if you want to
  run client assemblies *outside* Godot.
- The Godot download **must be the ".NET"/"Mono" variant** — the standard build
  can't run C#.
- Everything is cross-platform (Linux, macOS, Windows). Where a step differs by
  OS it's called out below.

## Get the code

```bash
git clone https://github.com/<you>/ashfelt.git   # your fork
cd ashfelt
```

There is no top-level solution file — each project builds on its own. The
[repository layout](../README.md#layout) shows what lives where; the
[codebase tour](codebase-tour.md) explains it.

## Verify your toolchain: run the tests

The fastest "is everything installed correctly?" check:

```bash
dotnet test tests/sim-core.tests
```

Green means your .NET SDK is healthy and the shared simulation builds. This is
also the test suite you **must** keep green on every commit
([why](../CONTRIBUTING.md#testing)).

## Run the server-side pieces

### World-server

One instance serves one region. Defaults: **UDP port 9050, seed 1337**.

```bash
dotnet run --project apps/world-server
```

### Gateway

Auth, character storage, and routing between world-servers. It needs a Postgres
connection string in the `ASHFALL_DB` environment variable and listens on
`http://localhost:5041` in dev (see
[`apps/gateway/API.md`](../apps/gateway/API.md) for the endpoints).

### Postgres + world-server together (Docker)

The easiest way to get persistence working end to end:

```bash
docker compose -f infra/docker/docker-compose.yml up
```

Schema migrations live in [`infra/migrations`](../infra/migrations) and are
applied in numeric order.

## Run the client (Godot)

1. Open the **Godot 4 .NET editor**.
2. Import / open the project at `apps/client`.
3. On first open, Godot compiles the C# and imports assets (fonts in
   `art/fonts/`, generated textures). Give it a moment.
4. Run the project. The boot scene is the title screen
   (`scenes/Title.tscn`); from there you enter the 3D world.

The client connects to `127.0.0.1:9050` by default. To test against a LAN
machine or a VPS, change `Host`/`Port` on the `WorldConnection` node.

### Controls in the editor

Ashfall is touch-first, but for desktop testing the editor also binds
**WASD/arrows** to move and the **mouse** to look. The real control scheme
(thumb-stick, drag-to-pan, tap-to-harvest, hotbar, menu) is documented in the
[README controls section](../README.md#controls).

### Putting `godot` on your PATH (macOS)

Godot ships as an app bundle with no CLI entry point, so `godot` on the command
line only exists if you add it — needed for the headless import used by CI and
by the art pipeline. **Use a wrapper script, not a symlink:**

```bash
cat > ~/.local/bin/godot <<'EOF'
#!/bin/sh
exec "/path/to/Godot_mono.app/Contents/MacOS/Godot" "$@"
EOF
chmod +x ~/.local/bin/godot
```

A symlink breaks C#: Godot locates its bundled `GodotSharp` assemblies relative
to its own executable path, so through a symlink it searches the wrong directory
and fails with `.NET: Assemblies not found`. `exec` from a wrapper keeps the real
path intact. (Full explanation in [`ASSETS.md`](../ASSETS.md).)

## Regenerating placeholder art (optional)

All art in `apps/client/art/` is placeholder art generated by a script. If you
change the generator or a tile layout:

```bash
python3 tools/gen_placeholder_art.py
godot --headless --import --path apps/client   # so Godot picks up new files
```

See [`ASSETS.md`](../ASSETS.md) for the atlas contract and licensing rules before
touching art.

## Continuous integration

Every push and PR runs [`.github/workflows/ci.yml`](../.github/workflows/ci.yml):

- **dotnet job** — builds `sim-core`, `shared-proto`, `world-server`, `gateway`,
  and runs `dotnet test tests/sim-core.tests`.
- **client job** — installs the Godot mono build, compiles the client
  assemblies, and does a headless project import as a smoke test.

Run the dotnet job's commands locally before you push and you'll rarely be
surprised by CI.

## Troubleshooting

**`dotnet test` fails to restore / wrong SDK.**
Confirm `dotnet --version` reports a 10.x SDK. The projects multi-target; a
too-old SDK can't build the net10.0 apps.

**Godot: "`.NET: Assemblies not found`" / scripts won't load.**
You're almost certainly launching Godot through a symlink, or using the
non-.NET build. Use the wrapper script above and the `_mono` / `.NET` Godot
download.

**Client connects but nothing happens.**
Make sure a world-server is running (`dotnet run --project apps/world-server`)
and that the `WorldConnection` node's `Host`/`Port` match it (`127.0.0.1:9050`
by default).

**Gateway won't start / character load 404s.**
The gateway needs `ASHFALL_DB` set to a reachable Postgres. The Docker compose
file wires this up for you; running the gateway bare means providing it yourself.
A `404` from `GET /characters/{id}` is normal for a brand-new device UUID — it
means "start fresh", not an error.

**Something else?** If a setup step didn't work as written, that's a
documentation bug worth fixing — open an issue (or a PR that corrects this page).
